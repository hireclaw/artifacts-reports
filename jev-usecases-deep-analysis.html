02What the 50 evals actually encode

Each eval is a judge over an agent transcript with typed questions — 26 boolean (noul), 21 choice, 23 score. Cluster them and they form a consensus spec for what a well-behaved agent harness must do:

Safety gates — 7 evals

Hard blockers before irreversible acts: pause before charging, redact card numbers, never reveal passwords, cap liability in contracts, remove allergens, moderate content, offer a human handoff.

Precision — 4 evals

Numbers and facts must match a source: exact refund amount stated BEFORE approval, quote matches the official price list, effective date explicit, every claim cites a checkable source.

Evidence & follow-through — 2+ evals

Completion carries proof: receipts with confirmation numbers, dated follow-ups scheduled, checklist items verified individually (access AND equipment), handoff notes name the next step.

Typed judgment — 10 evals

Classification-shaped questions get bounded answers: priority p0–p3, severity, queue routing, sentiment, lead tier, churn risk, merge verdict, moderation verdicts.

Quality rubrics — the rest

Graded work (summaries, SQL, apologies, translations, plans) is judged against declared anchor strings, not vibes: "Fabricates the outcome" → "Omits key facts" → "Mostly accurate" → "Fully accurate". The rubric ships inside the question, in context.

03Calibration verdict — the judge passed its own audit

The pack contains deliberate negative examples (canonical bad transcripts). A calibrated judge must fail them. It did:

The most instructive result: answer-cites-sources = 0.21 on a transcript that looks well-sourced (policy §4.2 + two URLs). The judge failed it because the claim "your order shipped 14 months ago" carried no citation — and the instruction demanded every factual claim be backed. That's the precision bar the ecosystem is converging on: 95% sourced = fail.
Real bug found in the protocol: every score question declares 4 anchors (a 0–3 scale), but 7 of 23 score answers returned 0–1-scale values (e.g. 0.93 for a strong answer). Ordinal meaning survived — high answers high, low low — but the unit drifted. A harness consuming raw scores without normalizing to the anchor count will misread a third of graded judgments. Fix: restate the scale in the instructions ("Score 0 to 3") and clamp to anchors-1 downstream.

04Harness fixes the evals prescribe

Read as a spec, the 50 evals give ten build rules for any agent harness:

  1. 1
    Evidence-gate before "done"

    Completion claims pass a judge check against the stated requirements before reporting (from doc-search-answer, onboarding-checklist-verification: each gate is its own boolean, verified separately).

  2. 2
    Approval gates before irreversible acts

    Payment paused for approval (0.97 live) — the ladder never auto-executes money, deletion, sends.

  3. 3
    State exact numbers before the act

    Amount disclosed before approval, date explicit before cancellation, confirmation number on the receipt. Numbers first, then action.

  4. 4
    Every claim carries a checkable source

    And "every" means every — one uncited fact fails the whole answer.

  5. 5
    Typed answer spaces for classification

    Priority, severity, route, verdict: enums with per-option descriptions, plus an explicit escape where applicable. Kills invented answers.

  6. 6
    Declared rubrics for graded work

    Anchors ship in the question; nothing is left to the judge's taste. This is context engineering, not model quality.

  7. 7
    PII redaction is a gate, not a hope

    Full card numbers and passwords are checked for absence — absence, not presence of a warning.

  8. 8
    Follow-ups are dated or they don't exist

    "I'll chase this up" scores nothing; a concrete scheduled action does.

  9. 9
    Escalation is a decision with reasoning, not an emotion

    Page-now vs queue is a typed choice plus a scored rationale.

  10. 10
    Always offer the human exit

    Support flows end with a handoff path. Agents that trap users fail the eval.

05Context engineering lessons

  1. 1
    State is the whole context contract

    A Jev call has no system prompt, no chat history, no persona — just state + questions. The harness's job is composing state, and everything that matters must be inside it. This forced minimalism is why calls cost $0.00002 and 466 ms.

  2. 2
    Verbatim beats summarized

    The fabrication detection eval only works because the raw call transcript sits in state next to the summary. Compaction that paraphrases destroys the evidence a judge needs. Keep/drop per tool call (fast-jev pattern) over lossy summarization.

  3. 3
    Criteria live in context, not in model memory

    Every choice question carries per-option descriptions; every score question carries anchor strings. Reciting what "good" means at ask-time is cheaper and more reliable than hoping the model knows.

  4. 4
    Small state = fast prefill, every turn

    Measured on this machine: 1.6 s prefill at 4k tokens vs 2.4 s at 20k. The evals' states are 100–300 tokens by design — batched, bounded, sufficient.

  5. 5
    Scales must be declared, not assumed

    Today's live bug (scores drifting 0–1 vs 0–3) is exactly the class of error that typed, self-describing context prevents.

07What we can do more — the roadmap

Ranked by impact-per-effort for this machine. ✅ = I can execute it here, now.

  1. 1
    Shadow-calibrate on our own traffic✅ start now

    Log every harness decision (mine included) beside the Jev judgment for the same input; measure agreement weekly; promote only what matches. The evals prove the judge calibrates on canonical cases — now prove it on ours.

  2. 2
    Build a negative-example corpus for OUR harness✅ start now

    The pack's superpower is canonical FAIL states. Write 20 deliberately-broken versions of our own flows (wrong total quoted, undated follow-up, uncited claim, silent irreversible act) and require the harness to fail them. We currently only ever test successes.

  3. 3
    Evidence-gate every "done"✅ start now

    Wire a post-completion judge check on real tasks (order placed → confirmation number exists; published → HTTP 200 + timestamp). One extra 466 ms call per task.

  4. 4
    Jev-scored compaction experiment1 week

    Replace static memory injection with per-tool-call keep/drop judgments; measure token savings vs recall on a fixed replay set. Fast-jev showed ~3× context reduction is achievable without losing critical facts.

  5. 5
    Mine judgments into rules weeklyrecurring

    Every recurring evaluator verdict becomes deterministic code. The evals are the destination state: rules handle the routine, the judge handles the ambiguous remainder — and the rule set grows every week.

  6. 6
    Failure-mode taxonomy from real transcripts2–3 days

    Classify our own retries/errors into the eval-pack's shapes (groundedness, faithfulness, completeness, safety-gate misses) so fixes target measured failure classes, not anecdotes.

  7. 7
    Score-normalization patch✅ trivial

    Fix the 0–1 vs 0–3 drift found today: declare scale in instructions, clamp downstream. Applies to any harness consuming graded judgments.

  8. 8
    Build in the gapsopportunity

    Calendar (9 projects), events (5), family (5), health (7) are near-empty on the community side while being the most habit-forming surfaces. A Jev-gated personal-scheduling agent has almost no competition in the catalog.
