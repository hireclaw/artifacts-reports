the origin · why not chat

ChatGPT broke Diogo Almeida's heart.

That's how TechCrunch opened its profile of the founder — and it's the whole thesis in one line. Almeida was an OpenAI researcher who helped build ChatGPT and co-invented RLHF, the training technique behind the entire chat era. His verdict on the result: "We have lightning in a bottle, and yet it is not useful."

His diagnosis: we spent four years optimizing models for human language, but automation runs on a different language. Computers need typed values they can branch on — not prose they must parse, validate, and second-guess. RLHF made models superhuman at pleasing people; it also made them overconfident, inconsistent, and dependent on humans-in-the-loop.

So TypeSafe took the opposite research direction: stop optimizing for human preference and start optimizing for calibrated decisions that software can act on directly. After two years in stealth, the company emerged on September 15, 2026 with a new architecture, a parallel sampler, and a new training algorithm — RLCD, Reinforcement Learning for Calibrated Decisions — and its first model: Jev.

"Think of Jev as a frontier-intelligence function call: unstructured state in, typed probabilistic decisions out."
— Diogo Almeida, founder, TypeSafe (launch post)

how it works · decisions, not strings

A frontier-intelligence function call.

An LLM generates one token at a time, each conditioned on the last. Jev does no autoregression at all: it reads a state, and answers all your typed questions in a single parallel pass — probability distributions, not text.

Noul
yes/no → probability, calibrated
Choice
one option from a set → distribution
Score
graded level on your scale → score + confidence
1 pass
all questions answered in parallel, same request
Existing LLMsSystem One + Jev
Trained withRLHF / RLVR — preference + verifiable rewardsRLCD — Reinforcement Learning for Calibrated Decisions
OutputsStrings — parse + validate; hallucinations possibleType-safe values defined in advance; type errors are mathematically impossible
SamplingSequential token-by-tokenParallel — all outputs in one query
ConfidenceOverconfident, inconsistentEvery answer ships with calibrated probability + confidence
End-to-end3–329 s (frontier)70–500 ms

Source: typesafe.ai launch post + docs.typesafe.ai/concepts/system-one. Up to 255 options per choice; higher cardinality uses a two-stage score-then-choose. Trained on synthetic data only.

the wire (real)
// one HTTP request: state in, decisions out
POST /v1/systemone
{ "model": "jev-latest",
  "state": { "ticket": "...", "customer": "..." },
  "questions": {
    "urgent":  {"type":"noul",
      "instructions":"Is this a refund request?"},
    "team":    {"type":"choice",
      "criteria":{"billing":"…","technical":"…","account":"…"}},
    "anger":   {"type":"score",
      "criteria":["calm","frustrated","very frustrated"]}}}
→ answers.urgent.noul = 0.95
→ answers.team.choice = "billing" + distribution
→ answers.anger.score = 1.4 + confidence

You declare the answer space, Jev fills in the probabilities; your code keeps the if-statements — act on high confidence, escalate low.

the workflow evals (a new kind of benchmark)

Instead of pass/fail Q&A, TypeSafe built evaluations where a real automation task is decomposed into code: deterministic rules + narrow typed questions. Every model runs the same harness; reference answers are the average of GPT-6 Astra and Claude Fable 5.1 at high thinking. Result: Jev owns the Pareto frontier for almost two orders of magnitude — nothing is both cheaper-and-more-accurate or faster-and-more-accurate.

The four published workflows: security incidents (close / escalate / contain), agent-trace observability (does a human need to review?), invoice processing (pay / hold / return), and customer service (what should the agent do next). Averaged across all four, every model scored better inside the workflow than as a one-shot prompt — structure itself is the win.

TypeSafe discloses its own biases: evals written by its capabilities team, reference answers biased toward OpenAI/Anthropic models, and pricing that "could be subsidized." Full receipts at evals.typesafe.ai.

the claims, stress-tested · zero hallucinations*

Can't hallucinate — but can still be wrong.

Hallucinated/invalid tool-call rates: LLMs leak; Jev is 0% by construction — the output space is defined in advance, so schema violations are mathematically impossible. (typesafe.ai)
the asterisk, honestly
· bounded output space prevents invented answers, not wrong-but-valid choices
· calibration is group-level: 0.90 ≈ 90% accurate in that band, no per-answer guarantee
· Jev gives up strings entirely — it cannot write text, reason step-by-step, or be your chat model
· architecture is closed; outside observers suspect an open-weight LLM base (TechCrunch)

The team is unusually candid — the launch post is titled around "receipts" and self-discloses demo caveats (the Doom bot is weaker than a scripted bot; wikiracing speedups shrink vs non-reasoning LLMs; the demo query "paints our model in an advantageous light"). Even the company's own head of devrel posted the limits plainly:

"Jev isn't perfect. We think it's still too slow, too expensive, and too dumb."
— Sasha Sheng (@hackgoofer), TypeSafe — "Let us know how Jev is bad!"

Armin Ronacher (Flask creator, CTO of Earendil — makers of the Pi agent harness) framed the operational bargain best:

"It delegates the hallucination problem a little bit to the user. If this comes back with 50% probability, maybe it's a coin toss. But if it's 95% — sure, then I can do something with it."
— TechCrunch, Sep 18, 2026

That confidence ladder is the real product: act when confident, escalate when not — thresholds set by your code, not by the model's vibes. In practice teams pair Jev with a big LLM: macro reasoning to the LLM, high-frequency micro verdicts to Jev. Skeptic Armin again: competitors "should have seen this earlier… you often don't have to be creative yet" because LLMs are cheap and subsidized.

verdict · the jevons thesis

Every drop in the cost of intelligence unlocks orders of magnitude more of it.

What's genuinely new: Jev is the first production model whose interface is decisions instead of language — a frontier-intelligence function call. It renames the split every agent team eventually discovers: LLMs are System 2 (slow, deliberate, general), Jev is System 1 (fast, typed, calibrated, composable). The ecosystem's verdict is already visible: 5,300+ repos in four days, two flagship projects at 6.4K stars and 3.7K stars, and platform listings on OpenRouter, Venice, Vercel AI Gateway and Cloudflare Workers AI.

What to watch: pricing sustainability ("can't prove it isn't subsidized" — their words), closed weights, single-vendor lock-in, benchmark self-disclosure (evals built by their own capabilities team), and the possibility that big labs simply add calibrated-logprob endpoints to existing chat models — exactly the objection Replit's CEO raised, and the thing to watch in the next two quarters.

onvoix verdict
BELIEVE the speed/cost claims — independently felt in production: ~300 ms batched decisions, output effectively free
BELIEVE the reliability claim directionally: typed outputs + confidence ladders remove the parse-and-pray layer
DISCOUNT the 193.6×/444.6× headline — use 40–200× as the planning range; treat "cannot hallucinate" as "cannot invent a type"
ADOPT for triage, routing, scoring, guardrails, compaction, agent gating. Keep an LLM for reasoning and prose. Escalate at low confidence — that's the whole design.
