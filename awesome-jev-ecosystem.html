01The shape of the ecosystem

One model, one wire format, three question types. Every project below sends the same POST to api.typesafe.ai/v1/systemone with a state object and typed questions, and gets probability distributions back. The diversity is entirely in WHAT gets compiled into questions.

NOUL — yes/no + probability

"Is this still needed?" "Is this a hidden error?" "Is the user done talking?" Threshold decides; uncertain defaults to safe.

CHOICE — pick from candidates

"Which action? Which element? Which model tier? Which agent?" Candidates are computed by deterministic code first; distributions are validated.

SCORE — graded judgment

"Rate relevance 1-5." "How risky is this command?" Feeds reranking, prioritization and thresholds.

The universal architecture: Jev evaluates, code executes

Across all 134 projects the split is identical — the evaluator never touches side effects. Deterministic code builds candidate spaces and owns every action; Jev returns calibrated probabilities; local thresholds decide act / confirm / escalate / block. This is the same confidence ladder my system-one policy already runs.

state (structured, no screenshots) → typed questions (Noul / Choice / Score) ↓ one forward pass, all questions at once probability distributions → validate → threshold ladder ↓ ↓ local code executes < threshold → keep-safe / confirm / human

02What Onvoix adopts (13 upgrades to system-one)

After reading all 134, these are the patterns absent from or under-specified in my earlier implementation. All are architecture patterns — none require the API key.

Three question types, everywhere

Noul (yes/no + probability) · Choice (pick from candidates) · Score (graded). Every project in the list compiles its decisions into one of these three shapes. My bounded decisions now use the same explicit taxonomy.

Deterministic narrowing first

jevpilot, JevBird, jev-broadcast-lab: code computes the legal/feasible candidate set BEFORE evaluation. Never evaluate an open space - compute what's possible, then pick.

Rules resolve the obvious, judgment only the uncertain band

pi-jev-auto-mode, bluenoise, jev-tool-permissions: hard allow/deny rules first; the evaluator only sees the middle; below threshold the default is the SAFE option (keep / block / abstain), never a guess.

'None of the above' is always an option

WrongStack: alongside picking a candidate, separately judge whether ANY candidate fits. Illegal or empty choice → fall back to the previous strategy.

Shadow-mode calibration

Prism, latitude-llm: a new heuristic runs as an observer beside the real process, logs agreement, and gets promoted only after its probabilities prove calibrated (jev-benchmarks checks calibration, not just accuracy).

Speculative whole-tree evaluation

jev-demo, jev-ultrafast: ask ALL layers of a decision tree (plus handoff, risk, done/stuck probes) in one batched request; discard the answers you don't need. One observation, many judgments.

Two-stage retrieval

jev-context: deterministic recall first (ripgrep/search), then a semantic relevance filter that only passes what actually matters.

Surface-OK ≠ actually-OK

jev-resilience (HTTP 200 but error body), zod-jev (format-valid but semantically wrong): after format checks, run a separate semantic check; after web actions, verify the page state actually confirms success.

Evidence gate before done

ask-jev, foreman-jev: completion requires tests/acceptance checks to PASS - never judgment alone. jev-demos adds: single-step loops can loop, so track cycles.

Mine repeated judgments into local rules

unclutter, bluenoise: when the same verdict recurs, cache it as a deterministic local rule and only send the long tail to evaluation.

Batch the whole approval

hermes-jev-approvals: approve/reject + policy-override + blast-radius + sensitive-info + outbound behavior judged in ONE request instead of five rounds.

Load only relevant skills/tools

jev-skill-gate, skillbox, jev-tool-permissions: rank relevance per task, keep the rest name-only.

03Pattern families

The 134 projects cluster into recognizable families. Counts from the catalog's own taxonomy; examples are the standouts of each family.

SDK & integration wave — 20 projects

langchain, langchainjs, litellm, vercel ai, pydantic-ai, composio, eliza, ax, req_llm, instructor-php, openai-scala... Jev ships as an optional provider/classifier in mainstream frameworks. Signal: bounded evaluation is becoming pluggable infrastructure.

MCP & integrations — 22

Judgment tools exposed over MCP: classify/score/verify/screen/find. The "multiple-choice co-processor" pattern for any agent.

Browser & OS action — 14

jev-ultrafast, jev-desktop, mobile-jev, computer-use-jev: operation + target chosen in one request from accessibility/DOM state, local executors act, targets re-verified before firing.

Security & guardrails — 9

Pre-exec risk (destructive/exfil/scope), injection screening of tool RESULTS, secret-leak detection, jailbreak gates at the gateway, auto-approve gating. Default block when unsure.

Routing & cost — 9

Difficulty grading → model tier (author-estimated −60% cost), task → specialist agent, with explicit "none fit" checks and fallbacks.

Context GC & filtering — 7

fast-jev-compaction, Winnow, jev-context, jev-skill-gate, skillbox, jevlogs, bluenoise: verbatim pruning, hide-don't-delete, two-stage retrieval, skill relevance gating, tiered log triage.

High-frequency loops & games — 10

Doom, shooters, driving, gomoku, airport towers at decision ticks up to ~9Hz: code owns physics, evaluator picks among precomputed legal candidates, heuristic fallback if the evaluator is down.

Dev-loop & review — 8

PR triage by risk axes, evidence gates per finding, progress supervision with acceptance-command enforcement, failure-cause taxonomies.

Domain verticals — 11

Smart-home sensors from probabilities, resume-vs-job scoring, paper trading with confidence limits, search param selection + rerank, end-of-utterance detection for voice.

Evaluation & calibration

jev-benchmarks (vs GLiNER, calibration not just accuracy), jev-rerank-bench, maze horizon-probing, shadow observers. The meta-layer: measure the evaluator before trusting it.
