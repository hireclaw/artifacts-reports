02 · The model

Needle 3 — one set of weights, every depth a model

Needle 3 is an intelligence ladder: every depth from 2 to 20 layers is a deployable model sliced from one set of weights. Trained on 360B tokens of proprietary structured data, it does three things — tool calls, structured extraction, and text embeddings — all as one JSON response with a calibrated confidence score.

04 · Deployment

Everywhere, from one file

Every deployment target ships a prebuilt engine under 1 MB that loads the needle3.cact weights at start. needle build --platform fetches the engine and places the weights beside it, at any depth from 2 to 20 layers.

05 · Tool design

The toolset is the product

Needle 3 does not chat — it picks tools and fills every argument from a span of the request. The same 121M model moved by close to twenty points on a mobile benchmark once every argument was grounded in the request instead of predicted freely.

From the blog · grounding — every argument copied from a span of the request
From the blog · one broad tool vs three narrow ones

The rules they ship with: one tool per action · enum names users would say · value formats in the description · bounds compiled into the decode grammar · regex triggers for unlistable phrasings · five or fewer tools per turn. Every response carries a calibrated confidence score — act when high, show and ask when middling, refuse when empty.

06 · The format

One file the kernel reads in place

Needle ships as one little-endian file the engine maps into memory and computes from directly: a 196-byte header carrying the whole architecture, 112 bytes of Lloyd-Max codebooks, a nameless 44-bytes-per-tensor directory, pre-transposed 64-byte-aligned blobs, and a self-contained tokenizer dump.

07 · Architecture

Channel mixing for almost no parameters

Needle replaces the transformer's feed-forward layer with three Kronecker-factored mixes that start as the Walsh-Hadamard transform and learn from there — 25.6K parameters per layer instead of 4.7M, and a fifth of the compute per token.

08 · Training

Intelligence ladders

One set of weights, every depth from 2 to 20 a deployable model. Subnetworks are chosen by bisection — start from the two endpoints, repeatedly split the widest gap at its midpoint — so they nest and stay spread through the stack. Training samples one path per step: 80% full model, 20% a random subnetwork pulled toward the full model by a self-distillation KL term.

09 · Platform and research

Fine-tune once, deploy any depth

LoRA of rank 16 trains on the frozen 20-layer base through 4-bit numerics, merges at export, and slices to any depth — one run serves every device budget. A few hundred examples move tool selection; thousands with reasoning lines move argument grounding.

From the blog · the fine-tuning pipeline, JSONL to tuned archive

Seven peer papers behind it

An attention-only transformer study, functional-factorised embeddings (ICML 2026), depth over specialisation in small multimodal transformers (ICLR 2026), calibration-aware activation sparsity, a fast LM-head replacement, token-aware chunked encoding and GRPO-guided hyperparameter controllers.

The Cactus Platform

The full path on their infrastructure: Cactus datasets, the 2-bit post-training behind the shipped model, evaluation design and tracking, full-depth fine-tunes and dataset management.

The verdict: Cactus is a research-led bet that automation — not chat — is the workload tiny devices need. One 29 MB file, 2.125 bits per weight, no cloud in the loop, and benchmarks where a 121M model beats 10× larger ones on exactly that workload.
